# Project Collaboration Rules

## Code Change Authorization

- By default, analyze the problem and provide a detailed implementation plan only.
- The plan must be suitable for review by another large language model before implementation.
- Do not edit code, configuration, tests, documentation, or other project files until the user explicitly authorizes implementation with wording such as "开始修改" or "改吧".
- Do not commit, push, restart services, deploy, or run commands that change external state unless the user explicitly requests that action.
- After review feedback is provided, update the plan first. Implement only after explicit authorization.
