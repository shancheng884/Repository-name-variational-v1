# NVDA 五档执行安全（2026-11-17）

本次修复针对 NVDA 五档实盘（entropy ↔ lighter_rh）中六个会直接影响资金安全的缺陷，
并补上可追溯的阻挡/成交日志。策略参数没有改：每笔 20U、累计 5 倍权益上限、
冻结中位数、回归平仓、双向方向锁全部保持原样。

## 1. 记账顺序：先成交，后记账

旧逻辑在 \`on_sample\` 里一次性把五档写入账本，再让 runner 下单；第一单还没发，
账本已经显示满仓，且单笔可能直接发 140U。

现在：

* \`on_sample\` 每个方向每个采样**只提议一档**，不写账本；
* runner 下双边单，成交后用交易所真实仓位核对，通过才调用 \`confirm_open\` 记账；
* 下一档要等这一档确认后才可能出现，累计上限仍是 \`5 × 较小权益\`。

## 2. 仓位对账不再把应持仓读成零

\`PositionLedger.net()\` 以前收到的是 asset 对象，键不匹配，期望仓位恒为 0，
正常成交会被当成异常并触发补平。现在账本内部统一用 \`asset.name\`（\`asset_symbol\`），
传入名称或对象都可以。

## 3. 成交确认不再虚报

* Entropy 超时兜底以前把**账户总仓位**当成本单成交；
  现在记录下单前仓位，只在“有向变化量 ≤ 1.5 × 下单量”时才算成交；
* 仓位读取带 2 秒缓存，\`settle_positions\` 现在要求 \`fresh=True\` 强制新读，
  避免用缓存证明成交；
* Lighter 的成交仍按 \`client_order_index\` 精确匹配。

## 4. 重启恢复

新增 \`log/nvda_tier_live_engine.json\`：档位、冻结锚点、入场价、手续费、
已实现盈亏、返佣、以及最近 2000 条 1 秒价差（约 33 分钟）。

启动流程：

1. 读取存档并重建账本；
2. 读取两个交易所的真实仓位与挂单；
3. 仓位不可读、有挂单、或与账本不一致 → 写 \`blocked_restore_mismatch\` 并退出，
   **不会**把真实仓位当空仓，也不会自动平仓；
4. 一致才进入预热/交易。

首次升级到本版本时若没有存档，会用 \`edges/cross\` 里同一 hub 的 1 秒价差补种基线，
不凭空造数据，也不重复 30 分钟预热。

## 5. 中位数窗口与确认

* 历史样本按**真实时间**裁剪到 \`--baseline-minutes\`（默认 30 分钟），
  并要求覆盖 ≥ 80% 窗口且 ≥ 120 个样本才算就绪；
* 同一对报价（sequence / recv_at / 可成交价完全相同）只计一次，
  两次确认必须来自两个独立报价版本，旧报价不会重复喂给确认窗口；
* 中位数改为对窗口内全部样本取中位数，不再只看固定 900 条。

## 6. 盈亏按真实四笔成交核算

平仓时用两腿开仓均价与两腿平仓均价计算：

\`\`\`
毛收益 bps = ((开仓卖价 - 开仓买价) - (平仓卖价 - 平仓买价)) / 开仓中间价 × 10000
净收益 bps = 毛收益 - (开仓手续费 + 平仓手续费) / 名义金额 × 10000
\`\`\`

* 手续费只扣一次，开仓费在平仓时统一结算，不会漏扣或重复扣；
* Entropy 110% 返佣单独记入 \`rebate_usd\`，不混进已实现盈亏，
  方便日后对账；最大亏损停机用的是扣费后的已实现盈亏；
* 任一条腿缺真实成交价时退回价差估算，并在记录里标 \`estimated: true\`。

## 日志

| 文件 | 内容 |
| --- | --- |
| \`log/nvda_tier_live_state.json\` | 当前状态、方向、价差、中位数、档位、\`last_block\` |
| \`log/nvda_tier_live_engine.json\` | 可恢复的档位/账本/基线/盈亏 |
| \`log/nvda_tier_blockers.jsonl\` | 阻挡原因流水：warming / below_threshold / quotes_missing / direction_locked / position_mismatch / open_not_hedged / restore_mismatch 等 |
| \`log/nvda_tier_orders.jsonl\` | 每笔开平仓的回执、结算核对、真实盈亏与返佣 |

\`last_block\` 会一直保留在状态文件里，不会被随后的 \`running\` 覆盖。
